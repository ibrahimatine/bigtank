Ta mission est de m'aider à construire une marketplace spécialisée dans la revente de chaussures grandes tailles (EU 46+ / US 12+).

CONTEXTE BUSINESS :

* Localisation : Sénégal (Afrique de l'Ouest)
* Devise : Franc CFA (XOF)
* Langue : Français uniquement
* Domaine : bigtank.com
* Cible : des milliers d'utilisateurs au Sénégal et en Afrique de l'Ouest
* Frais de port : gérés directement entre vendeur et acheteur (pas par la plateforme)
* Vérification vendeur (KYC) : non requise pour le moment
* Modération : les vendeurs publient directement, l'admin peut supprimer manuellement les annonces non conformes

MODÈLE DE COMMISSION :

* La première vente de chaque vendeur est GRATUITE (offre de bienvenue)
* À partir de la 2e vente : 100 FCFA par vente réussie
* Option à étudier : commission par publication d'annonce OU par vente uniquement
* Le système doit tracker le nombre de ventes par vendeur pour appliquer la règle

PAIEMENT — SOLUTIONS LOCALES (PAS DE STRIPE) :

* Fournisseurs : PayDunya, PayTech ou Naboopay (à intégrer via leurs APIs)
* Méthodes de paiement supportées :
  - Wave
  - Orange Money
  - Free Money
  - Carte bancaire (si supporté par le fournisseur)
* Le payment-service doit être abstrait (interface commune) pour pouvoir changer de fournisseur facilement
* Flux : acheteur paie via mobile money → plateforme retient les fonds → confirmation réception → versement au vendeur (moins commission si applicable)

ÉTAT DU PROJET :

* Projet from scratch — rien n'existe encore.
* Architecture : monorepo modulaire orientée microservices.
* Repo unique avec séparation claire des services (apps/ et packages/).
* Communication inter-services via Redis (Pub/Sub) et HTTP interne.
* Doit supporter des milliers d'utilisateurs simultanés.

STACK TECHNIQUE :

* Frontend : Next.js 14+ (App Router, Server Components, Server Actions)
* Backend : NestJS 10+ (architecture modulaire par domaine)
* Base de données : PostgreSQL 16 (via Prisma ORM)
* Cache & Queues : Redis 7 (cache, sessions, pub/sub, Bull queues)
* Temps réel : WebSocket via Socket.io (avec adapter Redis)
* Stockage fichiers : AWS S3 (ou S3-compatible : MinIO en dev)
* Paiement : PayDunya / PayTech / Naboopay (Wave, Orange Money, Free Money)
* Recherche : Meilisearch (recherche full-text, filtres, facettes)
* Emails transactionnels : Resend (ou SendGrid)
* Notifications push : Firebase Cloud Messaging (FCM)
* Conteneurisation : Docker + Docker Compose
* CI/CD : GitHub Actions
* Monorepo tooling : Turborepo
* Runtime : Node.js 20 LTS
* Langage : TypeScript strict partout

OBJECTIFS :

1. Construire une architecture propre, scalable et maintenable en monorepo microservices.

2. Implémenter une authentification sécurisée (auth-service) :
   * Email + password (bcrypt)
   * OAuth (Google / Facebook) — optionnel phase 2
   * JWT access token court (15 min)
   * Refresh token httpOnly sécurisé (7 jours)
   * Rotation automatique des tokens
   * Vérification email par lien ou code OTP
   * Reset password sécurisé
   * Login via numéro de téléphone (OTP SMS) — important pour le marché sénégalais

3. Implémenter le coeur marketplace (listing-service) :
   * CRUD annonces avec validation stricte
   * Upload images sécurisé (S3) avec compression et resize
   * Catégorisation : marque, modèle, taille (EU/US/UK), état, couleur
   * Prix en FCFA (XOF)
   * Système de tags et métadonnées
   * Pagination cursor-based performante
   * Publication directe (pas de validation admin requise)
   * Suppression admin possible (modération manuelle)

4. Implémenter la recherche et les filtres (search-service) :
   * Recherche full-text via Meilisearch
   * Filtres : taille, marque, prix min/max, état, couleur, localisation (ville/région)
   * Facettes pour compteurs dynamiques
   * Tri : pertinence, prix, date, popularité
   * Suggestions et autocomplétion

5. Implémenter le système de messagerie (chat-service) :
   * Chat temps réel (WebSocket + Socket.io)
   * Persistance des messages en base
   * Indicateurs : en ligne, vu, en train d'écrire
   * Historique des conversations par annonce

6. Implémenter le système d'offres et paiement (payment-service) :
   * Système d'offres / contre-offres / négociation
   * Paiement sécurisé via mobile money (Wave, Orange Money, Free Money)
   * Interface abstraite pour les fournisseurs (PayDunya / PayTech / Naboopay)
   * Commission plateforme : 0 FCFA pour la 1ère vente, 100 FCFA à partir de la 2e
   * Escrow : fonds retenus jusqu'à confirmation réception par l'acheteur
   * Gestion des litiges et remboursements
   * Historique des transactions
   * Webhooks pour les callbacks de paiement

7. Implémenter les notifications (notification-service) :
   * Emails transactionnels (bienvenue, confirmation, vente, offre reçue)
   * Notifications push (FCM)
   * SMS (pour OTP et confirmations critiques — via fournisseur local)
   * Notifications in-app temps réel
   * Préférences utilisateur (opt-in / opt-out par canal)

8. Optimiser la base de données :
   * Schéma PostgreSQL normalisé avec les entités : users, listings, images, offers, transactions, messages, conversations, notifications, reviews, seller_stats
   * Index composites sur les colonnes fréquemment requêtées
   * Pagination cursor-based sur toutes les listes
   * Soft delete pour les données sensibles
   * Audit log des actions critiques (suppression admin, transactions)

9. Sécuriser l'application :
   * Rate limiting (par IP et par user via Redis)
   * Protection XSS (sanitization)
   * Protection CSRF (tokens)
   * Validation stricte des inputs (class-validator + Zod côté front)
   * Gestion des rôles : user / seller / admin
   * Helmet.js pour les headers HTTP
   * CORS configuré strictement
   * Logs structurés (Winston/Pino)

10. Déploiement et DevOps :
    * Docker multi-stage builds par service
    * Docker Compose pour le dev local (tous les services + DB + Redis + Meilisearch + MinIO)
    * CI/CD GitHub Actions : lint, test, build, deploy
    * Environnements : development / staging / production
    * Variables d'environnement centralisées (.env.example documenté)
    * Health checks sur chaque service

11. Fournir du code TypeScript production-ready.
12. Expliquer chaque choix technique.
13. Anticiper les problèmes de scalabilité (milliers d'utilisateurs).
14. Proposer une roadmap d'amélioration continue.
